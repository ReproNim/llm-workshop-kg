ReproNim symposium worked experiment · 14 October 2026

A dataset, its papers, and a testable agent procedure

This experiment turns the skills section into a concrete scientific workflow. It builds a NIDM/PROV graph from the pinned ds000030 phenotype tables, connects selected paper claims to research questions and evidence, executes a bounded StructSense extraction, and derives a participant UMAP from graph queries.

Scope: complete coverage of the pinned phenotype tables, plus MRI inventory and selected acquisition metadata. This is not a complete raw-image-to-publication provenance reconstruction. Missing links remain explicit.

2. A source-to-derivative chain that was tested

The Barratt dictionary defines bis_parcel1 as the mean of items 19 and 17. For sub-10159 the source items are 2 and 2, yielding 2.0. Recomputing this formula matches the recorded value for 272 of 272 participants. The graph links each newly computed output to its computation and input record. The formula names the exact input columns.

This validates one behavioral derivation. It does not validate every variable marked as a derivative, and it does not prove the original historical software used this same execution.

3. Connecting behavior to image-derived phenotypes

A participant can connect a behavioral record to an imaging derivative. A usable imaging record must specify the measure, brain region, laterality, atlas/version, units, processing software/version, QC status and source imaging artifact. A visit or time-point link is necessary when repeated measures are possible.

Participant FreeSurfer stats and processing logs were not retrieved. Public derivative requests failed in this runtime. No participant imaging measurements or verified historical image-source links were invented. These proposed joins become executable only after importing the actual artifacts and checking their provenance.

4. A real phenotype UMAP

The matrix comes from a SPARQL projection of the graph. It contains 272 participants and 10 prespecified behavioral/cognitive scores: three Barratt second-order scores, three WAIS raw scores, quantile SSRT, ANT reaction-time conflict effect, CPT hits and CPT false alarms. Columns and participants needed at least 80% coverage/completeness. All selected participants and features passed; three missing cells were median-imputed. Columns were then standardized.

Diagnosis, age, sex and scanner were excluded from the inputs. UMAP used Euclidean distance, 15 neighbors, minimum distance 0.1, 500 epochs, and seeded random state 42 in the pinned UMAP-JS implementation. Diagnosis only colors the points.

Correlated score weighting, demographics and scanner sensitivity deserve further analysis. No diagnostic or causal inference was tested.

In Kim 2023, the graph attaches the reported 70.2% result to UCLA leave-one-out evaluation using both connectivity directions. Decreased-connectivity features yield 61.5% when training on UCLA and testing on COBRE. Reverse transfer does not predict above chance. These support a narrower conclusion than universal generalization or a causal mechanism. Questions here are curator formulations of the papers’ aims; numeric results are author reports.

The chain is question → claim → evaluation → cohort/model → dataset. Exact participant membership and per-file processing provenance remain unresolved. Sharing ds000030 does not establish use of the 2017 derivatives: the later paper reports GRETNA/SPM12.

6. The executed skill test

The pilot uses StructSense 0.12.0, pinned to commit dde54251…. It follows the structured-extraction reference and prompt, with a schema derived from the requested claim, evidence and scope fields. The host model authored six bounded records. The upstream span_validator.py ran unchanged. Ajv checked JSON Schema. Explicit vocabulary lookup and source review supplied alignment and faithfulness judgments.

This is a structured-mode subset, not an exhaustive extraction or a complete run of the NER/resource pipeline. The same host model performed review; it is procedurally separate, not an independent model assessment. Exact backend model identifier was unavailable.

Current evidence establishes bounded smoke tests and specific failure demonstrations. It does not establish skill-wide precision/recall, calibrated confidence or autonomous scientific reliability. SHACL checks a local six-shape NIDM/PROV profile, not all possible NIDM rules or the scientific truth of every triple.

8. Does the graph improve on LLM search?

The executed graph queries return exact participant counts, variable counts, a derivative’s provenance chain, a transfer claim and its qualifying evidence. The original inventory join returns 261 participants with both T1w and resting BOLD. Such joins, completeness checks, stable identifiers and explicit counterevidence are useful graph capabilities. Search is useful for discovery and interpretation. An agent with equivalent tables, code and constraints may perform just as well without RDF.

No controlled LLM-only versus graph-assisted performance experiment was run. A fair evaluation would compare search only, skill only, graph only and both, with the same corpus, model, tools and budget. Include a SQL/table baseline, independent gold answers, repeated trials, graph-construction cost and errors introduced during extraction. Score correctness, evidence completeness, unsupported claims, abstention, latency and cost.

9. A harness for reducing agent drift

The skill describes the procedure. The graph supplies persistent, versioned scientific state. The execution harness must enforce transitions: propose a change set, validate in a staging graph, review semantic changes, then promote accepted changes with a recorded graph diff. Pin input, skill, schema, prompt and software versions. Keep reported findings distinct from independently reproduced findings.

Drift typeConcrete controlEvidence here
Source/version driftReject unapproved manifest changesArchitecture specified; no long-session experiment

The graph can make drift detectable and reviewable. It cannot guarantee its prevention, and this pilot does not measure a reduction in long-horizon agent drift.

Across people, questions and publications

AbstractAtlas supplies a discovery surface and reusable claim/author records. The inspected repository snapshot independently rechecks source quotations, attaches evidence categories and ECO annotations, and records model/cache provenance. These checks do not prove scientific entailment. Its publication-space map and our participant-phenotype UMAP have different units of analysis.

The proposed collaboration layer represents a person’s work through a PROV activity: which question it addresses, which claims and artifacts it used, which result or review it generated, and which role the person held. Paper authorship does not automatically imply extraction, endorsement, ownership or review of every claim.

A concrete illustrative scenario connects analyst A’s question about added predictive information in Kim 2023 with analyst B’s question about reusable preprocessing in Gorgolewski 2017. Reviewer C assesses whether the processing evidence is relevant to the classification claim. Shared dataset identity alone does not prove shared participants or derivative reuse.

Keep cross-paper support, contradiction, relevance and equivalence as separately reviewed relations with their own evidence and attribution. Candidate relations from semantic similarity remain candidates. Comparisons need aligned populations, measures, direction, processing and evaluation conditions. Shared samples must remain visible to avoid counting dependent evidence as independent replication. Preserve conflicting assessments rather than replacing one reviewer’s judgment with another.

Identity also needs care: AbstractAtlas’s author builder deduplicates normalized name plus primary affiliation and assigns corpus-local numeric IDs. Cross-corpus joins should use verified identifiers or reviewed identity mappings, with unresolved candidates retained. Older contract files and current claim code use different field names; pin the implementation and normalize explicitly before import.

The package includes a separate illustrative collaboration graph, an executed query returning person/role/question/input joins, and a shape requiring reviewer attribution and evidence. It passes; deleting reviewer attribution fails. These records describe hypothetical contributors, not real historical work. This tests the model’s structural behavior, not an implemented AbstractAtlas collaboration feature.
